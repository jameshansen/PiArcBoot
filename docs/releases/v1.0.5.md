## What's changed

### New

- **An installer for every system.** `Install PiArcBoot` puts PiArcBoot in the folder you choose, with a shortcut on the desktop and an entry in the menu, in pages drawn in the RISC OS style with Back, Next and Cancel. Run again, it updates or removes PiArcBoot, and your games and saves stay either way. A copy installed by an earlier release, in `~/Games/PiArcBoot`, is found and updated in place.
- **PiArcBoot installs on Windows.** It goes in your own programs folder, with no administrator needed, and gets a desktop shortcut and a Start menu entry.
- **Install from a terminal.** One `curl` command on a Raspberry Pi or Linux PC, or one `irm` command in PowerShell, downloads the installer for that computer and runs it. Over SSH, with no desktop to show it on, it installs or updates PiArcBoot with the usual settings.
- **Portable copies.** Each system also has a zip that runs from wherever it's extracted, and keeps its games and saves in its own `Data` folder.

### Changed

- **Every download is a zip.** `PiArcBoot-Installer-<system>.zip` and `PiArcBoot-Portable-<system>.zip` for RaspberryPi, Windows and Linux-x86-64 take the place of `PiArcBoot.tar.gz`, `PiArcBoot-Linux-x86-64.tar.gz` and `PiArcBoot-Windows.zip`.
- Installing on Linux no longer needs zenity.
- The Windows download no longer carries 2.4 MB of the program's debug symbols.

### Inside

- The installer is a small program with the PiArcBoot folder packed behind it, which it unpacks to a temporary folder to run `piarcboot setup` from. The new copy is put together beside the old one and swapped in once it's all there, so a cancelled or failed install leaves things as they were.
- The release's `install.sh` and `install.ps1` fetch the installer from the release they came with, so an older release's script installs that release.
- Each push runs the Linux builds' installers, installing PiArcBoot into a test folder and running its self-tests from there.
